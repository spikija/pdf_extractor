# History v2 and patient-bound gender

`clinical_history.date_disease` stores an explicitly owned full date only. Month/year and year-only diagnoses use `date_disease_year`, `date_disease_month`, `date_disease_precision`, `date_disease_basis` and `date_disease_text`; they never receive a fabricated day. A current-admission proxy has its own `date_disease_proxy` and is not an exact diagnosis date.

Migration `0007_history_v2` adds these nullable fields, removes the history date's `CURRENT_DATE` default, and adds `clinical_history_evidence`. It does not backfill existing rows. Its downgrade refuses to discard populated v2 metadata or evidence.

The source-first parser retains numbered, category, nested and continued-page diagnoses. Source item IDs, parent item IDs and hierarchy levels distinguish independent child diagnoses from tests, procedures and treatment details. Every canonical projection keeps its exact evidence mentions. Limited chronic aliases and exact normalized labels are used; distinct dated events and unresolved identities are never silently collapsed. The best compatible direct temporal evidence wins. Conflicting chronology remains reviewable.

Generate a **dry-run only** artifact:

```powershell
.venv\Scripts\python.exe -m caa_pdf_extractor.extraction.clinical_history_v2 --patient 2834596323 --case-id 19 --dry-run --legacy-artifact <approved-history-artifact.json> --debug-root data/debug/history_v2_review
```

The legacy artifact is optional for source-only discovery. Providing the approved immutable artifact preserves previously validated narrative recall. Its checksum, source identity and exact quotations are checked. V2 artifacts fingerprint source content and the implementation dependencies. The v2 verifier rejects legacy v1 artifacts, stale sources, altered dates and unsupported evidence.

`history_v2.plan_commit` is a pure read-only plan. It blocks duplicate legacy identities and conflicting curated dates, and accounts for evidence links idempotently. This task does **not** provide an automatic v2 clinical write switch. A future controlled backfill needs separate authorization, a reviewed identity/merge manifest, backup, live case/source revalidation and exact row guards. It must not route v2 artifacts through the legacy v1 commit path. The existing v1 extraction interface remains available for compatibility.

`gender_evidence.extract_gender` accepts an explicit sex/gender field, one patient-bound age/Patient(in) statement, or at least two independent agreeing patient-bound markers. A title is bound using the same patient's identity header; names never determine sex. Addressees, relatives, repeated boilerplate and conflicting assertions do not produce an automatic patch. Case_v1 includes this evidence in its verified output and fingerprints the gender implementation.

Use the frozen cohort JSON for record-by-record date quality, exact evidence, exclusions and persistence holds. Validation artifacts are source projections and authorize no clinical writes. Historical PDF review packs were not regenerated by this development task.
