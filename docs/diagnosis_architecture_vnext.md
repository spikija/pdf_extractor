# Diagnosis architecture vNext — 4.3 candidates

The physician-facing registry is `patient_diagnoses.json`. It unifies supported diagnosis families without an acute/chronic split. Epilepsy source concepts are grouped under EPILEPSY; breast-cancer terminology is represented as BREAST_CARCINOMA. Event/history diagnoses retain `linked_event_ids` rather than collapsing their episodes into a single date. Legacy `canonical_disease_identities` remains available for compatibility.

`canonical_clinical_events.json` retains episode identity, event type/date/precision, date provenance, side, territory/location, etiologic assertions, evidence IDs and mention counts. `clinical_event_candidates.json` retains suspected, ambiguous and undated references for review. These references are not automatically additional confirmed events. The July 2018 suspected infarct remains UNCERTAIN with MONTH precision.

`admission_clinical_summary.json` is a separate layer per saved verified encounter. It contains probable admission diagnosis/event type, model confidence, exact supporting source spans, source method, source-summary hash, optional existing-event linkage and physician review fields. It is labelled PROBABLE_ADMISSION_DIAGNOSIS, never an automatically confirmed final diagnosis. Model abstentions remain null/LOW; missing summaries are marked explicitly rather than fabricated.

Admission inference uses the complete Zusammenfassung and its unheaded/summary continuation sections. Local Granite selects span IDs from a complete source index; Python resolves them to the original text, document/page/section and offsets. The existing Granite transport permits only numeric loopback HTTP, rejects proxies/redirects/cloud models and verifies an installed local Granite model. Structured diagnosis recognition does not call the model.

Local inference runs in the parent single-patient runner before the extraction worker. The request snapshots and hashes its model results. The worker retains its network/DB/subprocess prohibition and validates source hashes and span grounding again before materializing the separate admission layer. Implementation, prompt and source-result hashes are retained in module metadata. Browsing candidates does not call Granite; a new explicit diagnosis run does.

Admission/event linkage does not create a second stroke from an inferred label. It prefers an explicit source-supported date or the matching admission-date event. A transfer/rehabilitation source can link a unique anatomically supported historical episode without changing that episode's date. LOW-confidence results are not auto-linked. Admission-date fallback requires a pre-existing deterministic event candidate, explicit acute/current admission wording, positive source assertion and source-supported anatomy. Historical/transfer wording vetoes fallback. Existing event dates are preserved.

Assertion engine ASSERTION_SCOPE_1.3 adds CONDITIONAL for hypothetical future decision triggers, including “Sollte sich … Vorhofflimmer-Arrhythmie …”. CONDITIONAL, NEGATED, UNCERTAIN, DIFFERENTIAL and NOT_ASSESSABLE cannot establish AF. HISTORICAL remains a temporal attribute. An uncertain AF phenotype with negative objective monitoring preserves both facts. Independent positive source evidence is still allowed to establish AF despite other negative or conditional observations. Existing CAA predicate and acronym-scope safeguards remain active.

The Review App displays Patient diagnoses, Clinical events and Admissions under Diagnoses. Admissions use separate review IDs in the existing local diagnoses review/audit file, with ACCEPT, EDIT, REJECT and UNCERTAIN overlays. Unmapped structured diagnosis candidates remain mandatory, visible and part of the promotion gate. No source artifact is changed by physician edits.

Validation is limited to nine affected patients. Five controls are evaluated in memory and preserved on disk. Control 2953158925 has a documented baseline discrepancy: its stored positive AF assertion is a future contact-if-AF-occurs sentence. The new classifier treats it as CONDITIONAL; no control candidate or active artifact was changed.

The medication pipeline and dictionary are unchanged. The Phenobarbital issue for 2608083318 is OPEN/HIGH in `data/review/deferred_medication_regressions.json`, with reason ANTISEIZURE_MEDICATION. The queue is displayed without running medication extraction or normalization.
